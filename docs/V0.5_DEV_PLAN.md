# Agent Hub V0.5 Development Plan

V0.5 is the stabilization release that turns Agent Hub from a fast product prototype into a maintainable local agent workbench.

## Product Goal

Make Agent Hub reliable as the context owner for local agents.

The user should be able to keep one task open, attach files, switch between Hermes and OpenClaw, and trust that Agent Hub sends only the intended context to the active agent.

## Milestones

1. Context rules become explicit and testable.
2. SQLite becomes the primary session source.
3. Agent adapters expose one internal execution contract.
4. The current large frontend and backend files begin moving into modules.
5. A minimal regression test suite protects session, context, handoff, and adapter behavior.

## Sprint 1

- Align pinned attachment behavior between UI preview and backend context injection.
- Add backend tests for session persistence and context assembly.
- Keep localStorage for UI preferences, but stop treating it as the long-term session source.
- Document which data lives in SQLite and which data lives in browser preferences.

## Sprint 2

- Split backend storage and context logic out of `server.py`.
- Introduce a small Agent Adapter contract: `health`, `send`, `stream`, `capabilities`.
- Normalize Hermes and OpenClaw run records.
- Add failure-shape tests for agent calls.
- Keep `docs/AGENT_ADAPTER_CONTRACT.md` updated when adding adapter fields or new adapter ids.
- Add Claude Code CLI as the first post-Hermes/OpenClaw adapter to validate the contract.

## Sprint 3

- Split frontend rendering by area: task rail, messages, settings, context panel, agent switcher.
- Move API calls into one frontend API module.
- Add lightweight browser smoke checks for the main task workflow.

## Progress

- `context_engine.py` owns context formatting, summary helpers, and compaction.
- `storage.py` owns SQLite schema, session persistence, handoff records, and run records.
- `agent_adapters.py` owns chat execution and health checks for Hermes/OpenClaw/Claude Code.
- `agents.js` owns frontend Agent labels, profile normalization, run phase copy, and capability labels.
- `api.js` owns frontend `/api/*` calls.
- `state.js` owns frontend localStorage snapshots, local persistence limits, and browser-side redaction.

## Release Standard

Before each V0.5 sync:

- `python3 -m py_compile server.py`
- `node --check app.js`
- `python3 -m unittest discover -s tests`
- `./release.sh`
